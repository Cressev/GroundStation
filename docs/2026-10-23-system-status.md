# 系统状态页面与散热对照准备

## 页面使用

1. 在agentscope环境启动`python main.py`，连接机器鱼9999控制服务；进入“数据可视化 → 系统状态”（与XY轨迹、时间序列、姿态显示同级）。数据来自Pico，不是电脑CPU或电脑内存。
2. 正常的Pico控制桥每0.5秒推送state.telemetry，页面依次显示CPU占用率、CPU温度、内存占用率三幅独立图，顶部显示最新读数、已用/总内存MiB及更新年龄。首次CPU采样或不支持的字段显示缺失，不冒充0。画布区支持向下滚动，图之间的分隔条可拖动调整高度。
3. 全局模式保留并显示本页清除以来的全部历史；滑动窗口可填1～86400秒，仅影响可见范围，不删除历史。拖动/缩放某图只暂停该图跟随，其他图不动；“重置此图”只恢复该图，“重置全部”才同时恢复全部图。手动调整各图的横纵范围互不联动。
4. “清除曲线”只清本页并从下一包重新计时，不清深度/姿态曲线，不操作相机、运动或板端日志。
5. 先用“数据导出范围”选择CPU/温度/内存画布，再点“保存数据”选CSV/Excel；仅按所选图真正可见的X范围截取全部指标，不猜其他图的范围。包含秒、CPU%、温度℃、内存%、已用/总量MiB、大核MHz、电脑接收UTC、板端原时间戳、连接会话、实验标签和缺口标识。NaN/缺失字段留空。未保存的曲线只在内存中，关闭UI会丢失，长实验还应独立持续落盘日志。
6. “保存图像”保存完整三图区域PNG，各图保留自己的当前范围，含各自重置按钮；不只保存屏幕露出的上半部分。实验标签可填“电池/无风扇/室温”等；它仅随每行保存，不会切换真实供电或风扇。
7. 断线/超过2秒没新包会明确提示，旧值不按GUI刷新频率重复入库；下一包在曲线间插入缺口。重连保留历史并标记新会话，迟到旧连接包忽略。

## 采样和口径

- 横轴使用电脑接收事件的单调时钟，与Pico墙钟是否正确无关；同时保留源时间戳作证据。同一个源时间戳重复包不重复采样。
- CPU为板端/proc/stat整机汇总占用，不是load average、单进程占用或8核相加的800%口径。温度来自现有thermal_zone0；本次未改变传感器选择。
- 内存占用=(MemTotal−MemAvailable)/MemTotal；数值MiB来自原桥的KiB/1024，不等于进程RSS，也不是只看“free”。
- GUI采用Qt排队信号接收遥测，工作线程不直接绘图。现有9999协议已提供遥测，本次不需部署Pico或改控制逻辑。
- 单尾旧服务若没有telemetry字段，页面等待数据，不展示本机读数代替；需要板端支持才能画线。

固定同一块Pico、同一相机、同一分辨率/帧率、外壳/散热片/安装位置/线材及环境气流；只开相机采集传输，不开测距、图像增强或运动。风扇若与Pico共用5V，必须记录该附加负载与转速/供电电压；不能把两种风扇供电方式混作只比较风冷。

用户已确认每组15分钟；因电池供电问题，首组改为旧Pico、充电宝供电、未安装风扇，后续风扇从Pico的5V引脚取电（共用供电轨）。实验开始前先观测空闲温度，选所有组可达到的共同温度T0，每组稳定落在T0±1℃再开相机；建议该范围保持2分钟并记录实际起温/室温。不要为了赶进度在明显不同起温时开始对照；有风扇组也不能先吹至远低于共同起点。

安装/拆卸风扇和切换供电由用户操作，需断电时先保存日志并正常关机，不能带电随意接线。风扇全程是否上电要固定约定。每组保存全过程CSV/JSONL、相机实际FPS、boot_id/USB异常、供电/风扇标签，必要时绘制T−T0和温升/分钟。结束温度不等于稳态，15分钟未平台就如实说明。

不关闭系统/硬件原有温控保护，不在未说明时增加代理自定温度停止阈值。相机/网络中断或用户停止都如实标记为截断，不能误判成供电失败或散热稳定。

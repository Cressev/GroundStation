# 双目页录制按钮与统计

## 2026-11-06 更新：录像模式与命名

“高速原始双目录像”将相机原始左右 JPEG 按板端读取时间戳写入 MP4；不包括校正、画面提亮或测距点，实际收到多少帧就写多少帧，队列溢出会报错并保留部分文件。停止后保留原始 MJPEG 文件，并在电脑后台生成 H.264 兼容副本；对帧数、时间戳和总时长进行读回校验，不通过则提示并保留原片。两份文件占用更多空间，转码可能较慢并占用电脑 CPU。此模式需要新版 Pico 视频节点和 PyAV；连接新版板端时默认选择，进入录像时请求 30 FPS，结束后恢复原上限。旧板默认“显示画面录像”，也可以手动切回该模式，其仍按下面的 15 FPS 策略保存显示处理后的画面。

本机已在项目隔离目录安装 PyAV 17.0.0，并使用实际启动地面站的 `qt5` Python 3.10 测试导入及合成帧录像。另一台电脑缺少 PyAV 时，在实际运行地面站的 Python 3.10 环境运行 `python ref/install_local_pyav_runtime.py`；安装到 `.runtime/pyav` 而非 Conda 环境，已有目录不会覆盖。安装后重开地面站；若无法安装，仍可选择显示画面录像。

在“开始录制”旁输入可选文件名文字（不带扩展名）；非法路径字符或保留名称会阻止开始。停止后默认建议 `saved_data/stereo_videos/时间戳_文字.mp4`，未填写则只用时间戳，也可在对话框改路径；原片名追加 `_原始`。顶部跟踪录像直接保存到 `saved_data/top_camera_videos/`，记录带标记的页面显示画面，刷新约 10 Hz，不是原始相机最大帧率。截图、时序数据/图片、系统状态数据/图片分别进入 `saved_data` 的分类目录；自动命名不会覆盖已有同名文件。后台转码及录像文件转移不应阻塞 Qt 事件循环，但实鱼控制并发尚未验证。

连接机器鱼、连接视频并开启摄像头，收到画面后，绿色“开始录制”可用。按下变为红色“停止录制”；右侧空白区域显示例如`录制中 00:02:15 · 1620帧`。不可录制时按钮是灰色，不会仅用颜色区分状态。

再次点击停止并选择MP4保存位置。停止后保留本次时长和帧数，悬停统计可看完整保存路径；下次开始清零。断线、关闭相机或退出会沿用原自动保存逻辑，计时也停止。开始后还没有新帧就停止，不生成空视频。编码器初始化/写帧异常显示“录制失败”，保留此前帧数，不继续假计时。

时长为单调时钟计算的实际经过时间，每250ms刷新；没有新画面时，时间继续而输入帧数不增加。显示画面模式的帧数统计提交给本地录像的处理后画面（左右目合为一帧），不是网络接收帧率或摄像头原始帧率。该模式后台线程按15 FPS时间轴采样最新画面：输入较慢时保持上一画面，输入过快时取最新画面；停止后将输入帧数和包含补帧的编码帧数写入统计悬停提示。编码持续落后超过2秒或写入失败则显示失败并保留已有部分。高速模式统计提交的原始双目帧，不补帧，时间戳反映板端读取时刻而不是硬件曝光时刻。点击测点的重绘不额外录帧。

按钮分连接和录像两排，窄屏无需横向滚动。板端已运行支持高速录像的视频服务时，本次依赖和布局修复只需停止录像并重开地面站；运行中的旧进程不会热加载。无需修改 STM32 固件。

## 离线复现

操作目的：独立合成画面验证颜色、真实MP4时长及左右目尺寸，不连接机器鱼；每轮输入30帧，编码帧按真实经过时间计算；截图和JSON摘要保留在输出目录。

```powershell
cd D:\Documents\Study\codex-fish\src\GroundStation
conda activate agentscope
python -X utf8 ref/verify_stereo_recording.py --output ../../tmp/stereo-recording-manual
```

输出目录必须不存在。预期摘要中`decoded_frames`与实际时长×15相符、`decoded_shapes: [[320,240,3]]`、`start_color: #15803d`、`stop_color: #b91c1c`、`hardware_touched: false`；帧数可因运行时长变化。窗口自动关闭，MP4和截图仍留在输出目录。只有合成画面，无硬件接线要求，不调用摄像头或网络。

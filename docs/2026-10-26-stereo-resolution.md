# 双目测距页选择采集分辨率

## 使用方法

电脑与Pico通过原有有线网络连接，相机仍接Pico的USB，不改变供电和控制接线。

1. 保存当前数据和录像，关闭所有运动控制。退出旧地面站再打开；本轮没有替你关闭正在运行的窗口。
2. Pico视频源码已备份更新，旧进程不会热加载。准备好中断现有连接后，在Pico重新运行原入口：

   ```bash
   setsid nohup bash /root/catkin_ws/src/pico_stereo/scripts/start_dual_fish.sh > /root/dual_fish.log 2>&1 < /dev/null &
   ```

   预期约17秒后原五服务与监控恢复，日志出现`relay_listen`，相机默认关闭。此操作会使现有连接断开；本轮代理没有执行。
3. 地面站选择双尾鱼，连接机器鱼→连接视频。预期“采集分辨率”出现服务公布的双目档位，而非预填的通用相机分辨率。
4. 摄像头已开启时先点击“关闭摄像头”。选择档位→“应用分辨率”，等待确认。“下次采集”显示实际选中值，再点击“开启摄像头”。
5. 测距必须加载与当前**每目尺寸**、左右关系及环境一致的最终NPZ。失配时红字说明尺寸差异，清空旧距离/测点，测距按钮禁用，但原始第一目仍可预览和保存。加载匹配NPZ后恢复校正图和电脑测距。

应用不会自动开启相机。切换期间、相机开启、保存录像期间不能修改尺寸；超时只查询状态，不重复发送切换。失败恢复板端实际档位。断开重连重新读取，不自动抢相机，也不自动恢复旧选择；服务重新启动后的初始尺寸仍由板端默认NPZ决定。

## 分辨率含义

| 每目图像 | 实际横拼采集/传输 | 当前相机MJPG枚举 |
|---|---|---|
| 320×240 | 640×240 | 有 |
| 640×480 | 1280×480 | 有，默认 |
| 800×600 | 1600×600 | 有 |
| 1280×720 | 2560×720 | 有 |
| 1600×1200 | 3200×1200 | 有 |

UI选项来自Pico的UVC枚举与本型号已知双目横拼布局的交集，不直接展示全部UVC模式。`1280×720`原生**单目**模式不作为双目横拼使用。换其他型号需先核实其帧布局。

图像显示顺时针旋转90°，因此每目1280×720保存为720×1280（宽×高），依然只有一目。未匹配标定时显示“原始第一目”，与标定指定的逻辑左目可能不同，不应拿其图像当已校正测距结果。算法、自动曝光/gain120/Gamma2.0未修改；发送上限仍15FPS，但不保证高分辨率实际采集、网络或SGBM达到15FPS。

## NPZ与兼容性

不缩放校正map、不修改Q、不猜内参。重复状态推送不会悄悄重设选择；切回原尺寸后可复用缓存的原NPZ。高分辨率原生NPZ四张float32映射会超过旧8MiB，本地最终NPZ现在最多32MiB；解压总量仍最多32MiB、字段数量/格式/有限值等校验不变。板端默认NPZ传输仍保留8MiB限制，本地高分辨率文件不上传。

旧服务没有分辨率能力字段时，下拉置灰并提示升级；原预览兼容，不能假装只升级UI就已改变采集。协议扩展`resolution_options`、`resolution_switch`；命令`SET_RESOLUTION <横拼宽> <高> <请求ID>`仅在摄像头关闭时接受。原CAM_ON/OFF、GET_STATE、GET_CALIBRATION不变，仍拒绝RANGE_ON。

## 验证与边界

235项自动化回归（219项地面站＋16项relay/协议）通过。真实Windows窗口连接合成TCP relay，应用2560×720后假相机收到该尺寸；失配无距离，匹配14,747,220字节的本地NPZ后同帧点击得到合成80cm，PNG为单目720×1280；640宽窗口无横向溢出。

旧Pico实际只读枚举确认五档；另一个独立对象不打开相机、不监听端口，逐档配置验证通过。板端更新前后原video PID1091、boot及9998/9999连接保持。**未重启现有服务，未做真实相机逐档采集/距离精度/帧率验收。**

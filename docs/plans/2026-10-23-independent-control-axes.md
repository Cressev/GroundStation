# 航向与深度控制解耦实施计划

**Goal:** 左侧上下两独立通道支持键盘/Xbox与单闭环深度PID组合，各自选型启停，系统日志移右下，控制区可滚动。

**Architecture:** 保留现有键盘/Xbox与PID运算，新增纯指令协调器。航向只拥有尾鳍，深度PID启用时独占胸鳍；
仅协调器输出完整指令到通信层。保留旧DepthController作兼容/算法回归，新DepthAxisController仅暴露PID页和胸鳍输出。

**Tech Stack:** Python agentscope、PyQt5、现有ControlCommand/PID、pytest、真Windows Qt离线假通信。

## ADR：单出口与显式执行器归属

状态：按用户2026-10-23要求实施第一版。

两个完整控制器直接各发串口/TCP会争抢执行器；只改UI分组仍留下深度绑定键盘，因此不采用。
采用一个协调器统一合成，代价是需明确每次启停和交接；收益是来源门闩、单出口、安全测试可独立复现。
不增加微服务、不改板端协议，不实现未来IMU双环，不触发相机/板端实验。

主要状态与失败策略：

- 两路默认关闭，真实主连接就绪后才可启用，各自运行时锁定自己的类型；另一通道不受影响。
- 用户追加确认：各自未启动时参数置灰，启动成功后直接可调；深度不再需要额外解锁。全停/紧停/断线恢复置灰，保留类型选择和未应用输入。
- 仅航向：尾鳍沿用键盘/Xbox，胸鳍仍可QE/Y/A/RT手动；仅深度：尾鳍为0，胸鳍闭环。
- 组合：尾鳍由航向来源控制，胸鳍由PID控制；明确锁住手动胸鳍，不能后台累积手动偏移。
- 单独停航向只停尾鳍，PID继续；单独停PID清空积分，从最后实际PWM交回手动，不能跳回旧手动值。
- 深度启动等待新样本，超时复用原策略回中，P/I/D及限幅和坐标极性不变。
- 全停/断链/关闭：先撤权、停定时器，再发一次安全帧（主动断开时）；断链不能自动重启。
- Xbox X/B或手柄断开：立即停尾并撤销两路，保持最后实际胸鳍值，拒绝后续迟到输出。
- 旧来源、停用来源和运行中类型切换均拒绝；重复启停/切换幂等；单尾旧路径继续维护。

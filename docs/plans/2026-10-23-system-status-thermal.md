# 系统状态曲线与散热对照实施计划

> 按用户要求在当前会话顺序实施，不另开工作树或委派代理；缺少superpowers子技能时用现有Code工作流验证。

**目标：** 地面站增加独立系统状态页，先验证界面，再开展电池/充电宝×有/无风扇摄像头持续运行四组散热对照。

**架构：** 复用Pico现有9999 state.telemetry（2Hz），不修改板端控制、相机或安全保护。Socket回调通过携带连接实例的Qt排队信号交给GUI，按真实收到的新包采样，使用电脑单调时钟作横轴、保存板端原时间戳。独立历史不受深度曲线清除或滑窗影响。

**技术：** agentscope Python、PyQt5、pyqtgraph、CSV/XLSX/PNG。

## 1. 备份与先写回归

- 读取main_window.py当前版及板端遥测格式；备份到tmp/gs_system_status_20261023_1643/backup/。
- 新建tests/test_system_status.py：缺失/非法值不冒充0；CPU/内存单位；全局/滑动/手动范围；当前画布CSV/XLSX；断线缺口、清除与重连；Socket线程不直接改UI，迟到旧实例忽略。
- 执行agentscope pytest，确认新模块未实现时失败，再写最小实现。

## 2. 独立系统页及连接门闩

- 新建ui/system_status.py：三幅联动曲线、最新读数/反馈年龄、实验标签、全局/滑窗/可填秒数、清除/重置/保存数据/保存PNG。
- 修改ui/main_window.py：中央新增“系统状态”，遥测排队转GUI，连接、断线和关闭复位；不改运动和测距路径。
- 每个函数/类保留docstring，语法/编码自检；旧遥测底栏继续使用。

## 3. 验证与文档

- 新建ref/verify_system_status.py，用假通信长时序与实际Windows窗口验证缩放/保存/缺口，禁止连板/运动/写个人配置。
- 全量相关回归；截图由代理检查后交付。README、docs索引、finding及长期记忆同步；Git只提交本任务代码/文档。

## 4. 实验启动前条件

- 四组相同Pico/相机/相机分辨率/帧率/预览工作量；只开采集传输，不开测距、图像增强或运动；环境温度、外壳/位置/气流尽量一致。
- 用户确认每组时长、当前供电/风扇及风扇供电方式。建议每组30分钟；每组开始温度落在同一目标±1℃，记录冷却过程，不能把不同温起点当严格对照。
- 先读SSH地址并只读核查实际源码/运行进程/相机占用；已有人工运行服务不擅自关闭。需要用户切换硬件；不擅自改温度/内核保护或新增主动停止阈值。
- 原始遥测持续落盘，记录启动温度、CPU/内存、实际帧率、断连/重启和供电/风扇条件；实验报告存docs/test-reports/pico/<实验编号>/report.md，配图同目录assets/。未确认接法、未完成四组时如实标记待测，不能编造对照结果。

# 双目高帧率录像测试实施计划

**目标：**在每目 1600×1200 条件下测量真正的新帧录像帧率，同时保持录像时间与实测时间一致，不影响机器鱼控制。

**架构：**先检查设备身份及占用；不启动控制节点，用隔离测试链路传递相机原生 MJPEG 和逐帧时间，记录采集与接收帧号、时间、CPU 和编码；结果仅作为候选，不替代生产链路。再按瓶颈决定实际产品改动；与控制服务同时运行及真实用户操作须单独验证。

**技术栈：**agentscope Python、OpenCV、PyAV、SSH、Pico V4L2。

1. 验证采集模式、曝光、占用、板端版本，记录原始条件并保留现有文件。
2. 使用带时间戳的有界传输和独立保存，尝试 15、20、25、30 FPS；核对帧号、单调时间、时长、重复/丢帧和实际文件解码。
3. 记录两端 CPU、内存与温度；不发送控制指令，避免与现有相机连接冲突。单独辨别相机、网络、解码、录像瓶颈。
4. 如果离线和实测支撑优化，备份源码后实现、测控制隔离并写使用说明；中文提交推送。无法实测的部分如实标注。

## 本轮进度与边界

2026-11-06 已在隔离端口比较原有 BGR 重编码与原生 MJPEG 采集：最大分辨率分别约 15.75 FPS 和一分钟 28.98 FPS，后一视频逐帧时间戳封装并验证；[正式报告](../../../../docs/test-reports/pico/stereo_high_fps_20261106/report.md)。未修改或部署正式视频服务，也未将高帧率录像集成 UI；控制链并发及独立曝光尚待验证，不应将原型当正式功能。

# 高速录像和保存命名实施计划

**目标：**安全地接入真实时间戳的高速原始双目录像，并为录像和曲线导出提供合法文件名与专用默认目录。

**架构：**保留原有显示画面录像；高速录像从原始双目 JPEG 接收线程进入有界异步队列，使用板端帧时间封装可变帧率 MP4，不重复补帧；保存原始图像，不带校正及测距标记。Pico 视频节点优先原生 MJPEG 并保留原实现回退，控制节点不改；命名和默认目录由公共函数统一管理。

1. 备份本机源文件，核对板端源码哈希与现有服务状态，不中断既有连接。
2. 验证跨平台文件名、时间戳与冲突处理；视频、时序、系统状态和图像导出默认进入 `saved_data` 对应分类，允许用户在对话框改路径。
3. 添加有界高速录像、时间戳与故障恢复测试；Pico 原生采集需覆盖打开、无帧、EOF、异常、停止和回退，不能阻塞视频线程或控制链。
4. 不发送舵机命令，执行相关及完整离线回归；在独立端口完成实物视频录制、时长/帧数解码与资源释放验证。未验证的控制并发如实标注。
5. 更新中文说明，精准提交本项目改动并推送；设备设置、实验数据和临时文件不纳入提交。

## 完成与保留边界

旧 Pico 视频源码已备份并部署，高速原始录像和分类命名已实现；最大分辨率下最终以地面站实际写入器保存 577 帧/20.329 秒，板端部署后独立端口约 28.95 FPS。测试未运行控制桥或实鱼，不能宣称已验证真实控制并发。完整记录见项目根目录 `docs/test-reports/pico/stereo_high_fps_integration_20261106/report.md`。
